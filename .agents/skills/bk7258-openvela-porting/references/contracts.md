# 驱动、媒体与跨核合同

## 必查问题

1. upper/lower初始化、open、stop、shutdown、close各在什么上下文？是否持锁，回调能否重入？
2. 谁分配、持有、交接和释放帧/PCM/消息？使用系统堆、SDK池还是DMA域？
3. 正数部分进度、EAGAIN、超时、主动取消、真正故障如何区分？
4. 队满、重复启动、对端失联和迟到回复是否留下旧owner或任务？
5. generation、序号、deadline在会话/重启后如何变化？
6. DMA/cache/共享内存和多核发布顺序是否满足实际硬件？
7. 新配置是否同时进入源选择、链接、board注册与生成.config？

## 分层定位

寄存器/IRQ/时钟/DMA改chip；器件/引脚/电源时序改board；用户交互与媒体编排改app；会话/模型网关改server；输入身份与分区验证改build工具。新功能先确定最小边界，再沿已有子系统接入。

失败验证优先使用真实被改实现；mock只替代硬件或外部服务。退出后检查资源和状态，不能只检查返回码。
