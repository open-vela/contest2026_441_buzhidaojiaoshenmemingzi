# 证据门禁

## 移植门禁

| 门禁 | 最小证据 |
| --- | --- |
| P0 硬件身份 | R1 板号、SoC/Flash/PSRAM/codec/传感器 ID、引脚和分区来源 |
| P1 可恢复构建 | 固定版本、工具链、干净构建命令、镜像清单、备份与恢复步骤 |
| P2 CPU0/NSH | 连续完整启动日志、NSH 命令响应、复位后可重复 |
| P3 内存/GPIO | PSRAM 压测、关键 GPIO/定时器实测、异常路径 |
| P4 网络 | Wi-Fi 连接、地址、收发统计、断网和重连 |
| P5 相机 | 真实 V4L2/DVP 采集、格式/尺寸、至少 100 帧、主机解码验证、错误与资源统计；哈希用于关联样本，不替代解码 |
| P6 音频/反馈 | 真实录放音或 codec 路径、格式/时长、可感知反馈、错误与资源统计 |
| P7 应用闭环 | 真实输入到输出、时延边界、离线/设备缺失/服务失败样本 |
| P8 稳定与上游 | 长稳、重复开关、内存趋势、差异最小化、可审查提交 |

只有通过当前功能真正依赖的门禁，才提高“已验证”级别。编号用于里程碑索引，不强制串行：离线采图不依赖 P4 网络，音频可独立验证。表中 100 帧等数量是本项目的测试目标，不是对大赛规则的引述。

## 大赛能力判定

### 图形

项目代码必须通过 openvela/NuttX 显示栈驱动目标板显示器，并提供可见画面、分辨率/格式、启动日志和异常证据。BOM、Kconfig、mock、计划或上游示例均不算落地。

### AI

真实模型或智能体必须接收真实输入并产生可复现输出，同时记录模型/服务身份、时延边界和失败处理。接口占位、硬编码结果、返回 ENOSYS 或仅有方案文档不算落地；MiMo 不是唯一实现方式。

### 多媒体

项目必须通过 openvela/NuttX API 实际采集或播放相机/音频数据，并记录格式、数量/时长、数据有效性、错误和资源变化。只探测设备节点、只写路径、只运行厂商独立 demo 不算落地。

## 状态词

- 规划：只有设计和待办。
- 接口占位：调用链存在，但后端未实现或返回 ENOSYS。
- 实现存在：代码已写，尚未完成构建。
- 构建验证：在固定基线上干净构建通过。
- R1 实机验证：真实发放硬件运行通过并保留原始证据。
- 能力落地：满足相应能力定义，且结果可复现、可审查。
