# 团队作品开发规划

## ① 项目名称与一句话定位

项目名称：**基于 openvela 的视障随行视觉辅助胸牌**。

一句话定位：面向具有独立出行能力的视障用户，使用 BK7258 R1 对话式 AI
套件开发免手持视觉辅助设备，帮助用户在到达目标区域后发现和确认入口、门牌、
站点标识与公共服务设施。

## ② 目标开发板及选择理由

目标开发板：**对话式 AI 开发套件 R1（声网 & 博通集成，BK7258）**。

选择理由：

- 大赛统一发放，便于官方支持和结果复现；
- DVP Camera、双麦/本地 AEC、扬声器、Wi-Fi、双屏、触摸与振动覆盖应用需求；
- BK7258 具备面向音视频的多核、硬件编解码和外部 PSRAM 能力；
- 声网与 Beken 已公开相近硬件的完整 ARMINO 音视频示例，可作驱动对照；
- openvela 社区已有 CPU0/NSH 和板级 bring-up PR，可缩短从零探索时间。

官方当前仍将其列为“待适配开发板”。因此本项目把 BK7258/openvela 适配纳入
正式工作，不把公开 PR 的结果冒充本队真机成果。

## ③ 核心功能与硬件能力

| 核心功能 | 用户价值 | 所需硬件能力 |
| --- | --- | --- |
| 平台适配与能力验证 | 确保基础平台稳定、资源可测 | BK7258、Flash、PSRAM、UART、Timer、GPIO |
| 视觉目标发现与确认 | 确认入口、门牌、站点、设施和大致方位 | DVP Camera、Wi-Fi |
| 标识与文字信息获取 | 读取门牌、站名、入口与楼层标识 | Camera、Wi-Fi |
| 语音交互与反馈 | 自然语言提问并获得免手持反馈 | 双麦、AEC、Wi-Fi、Speaker |
| 状态与方向提醒 | 断网、处理中、成功和左右方向等简洁提醒 | 振动、音频，可选双屏 |

## ④ 技术方案

1. **平台基线**：复核公开 PR，先让 NuttX 运行于 CPU0，经 UART0 进入交互 NSH，
   再验证 SysTick、堆、PSRAM、GPIO 与镜像打包。
2. **网络**：保留厂商 RF/PHY 和校准能力，在 vendor 层做最薄适配，向 NuttX
   暴露标准 netdev；验证 DHCP、DNS、TLS 和掉线恢复。
3. **视觉**：DVP + DMA 采集按需单帧，PSRAM 保存帧，目标通过 V4L2
   `/dev/video0` 暴露；JPEG 经 HTTPS 上传 MiMo。
4. **语音**：双麦采集 16 kHz/16 bit PCM，AEC/NS 作为可开关处理层；ASR、
   视觉理解和 TTS 由云端完成，Speaker 播放结果。
5. **反馈**：第一阶段先用 NSH/控制台形成可审计闭环，随后接入振动和音频；
   显示用于状态和演示，不作为无障碍交互的唯一通道。

## ⑤ 开发顺序

优先建立 P0～P2 最小可恢复启动基线，同时推进应用接口、状态机和主机测试。
各实机功能按依赖验收，不要求 P0～P6 全部完成才开始应用开发；离线采图可与
网络并行，完整语音属于后续阶段。应用服务接口和状态机保持稳定，使 Wi-Fi、
Camera、Audio 可在底层分别替换。详细阶段与退出条件见
[BK7258 R1 移植计划](BK7258移植计划.md)。

## ⑥ 主要风险

- 公开 PR 尚未合并，可能 force-push 或被 review 要求重构；
- 发放 R1 与公开 BK7258 DevKit 可能存在引脚、屏幕或存储差异；
- NuttX 运行于 CPU0 后，厂商 Wi-Fi/A/V 多核库的依赖关系可能改变；
- Camera、TLS、音频同时工作时 PSRAM、DMA、cache 与内部 SRAM 峰值较高；
- 出厂校准区或分区被误擦会导致无线性能下降，烧录前必须具备恢复方案。
