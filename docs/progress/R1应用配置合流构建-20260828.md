# R1 应用配置合流构建

日期：2026-08-28。

## 目的

确认 `contest2026_441_vision_badge` 不是另一套退化的系统配置，而是在已经实机
验证的 R1 NSH 基线上增加 `vision_badge` 应用。本文只记录构建、链接和打包证据；
在烧入本队开发板前，不把它标记为实机通过。

## 配置修正

应用 defconfig 补齐以下已验证基线：

- `CONFIG_ARMV8M_SYSTICK=y`、`CONFIG_TIMER=y`、`CONFIG_TIMER_ARCH=y`；
- `CONFIG_ARCH_BUTTONS=y`；
- `CONFIG_LVX_USE_DEMO_CONTEST2026_441_R1_KEYLED=y`；
- 保留原有 RAMLOG `/dev/kmsg` 和 `vision_badge` 配置。

原因是两个 defconfig 分别生成完整 `.config`。选择应用配置不会自动继承 `nsh`
配置；必须明确同步共同基线。

## 构建与 ELF 检查

执行：

```sh
cd /home/alientek/openvela/contest2026_441_buzhidaojiaoshenmemingzi
bash scripts/build.sh app -j4
bash scripts/package.sh app
```

干净构建完成 1136 个 Ninja 目标，链接占用：Flash 194168 B、内部 SRAM 静态占用
13496 B。ELF 为 `ELF32`、ARM，入口为 `0x02010141`。全局符号中确认存在：

```text
up_timer_initialize
ramlog_syslog_register
r1keyled_main
vision_badge_main
```

因此四部分不只是通过编译，而且均进入最终 ELF。
