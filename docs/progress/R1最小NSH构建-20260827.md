# R1 最小 NSH 构建与打包记录

日期：2026-08-27，实机验证更新于 2026-08-28。结论：**本队独立
`bk7258-r1` 板级目录已经完成 CPU0 + UART0 + NSH 编译、CPU0-only 镜像
打包和 R1 实机烧录，能够稳定进入 `nsh>` 并进行双向串口交互。系统时钟
尚未通过验证，`sleep 5` 不能返回，作为下一项独立问题处理。**

## 本轮代码边界

- 板级层：`board/bk7258-r1/` 保存可构建的完整 R1 最小目录，包括 `nsh`、
  后续应用 defconfig、链接脚本、初始化骨架和 `repack.py`。
- 芯片层：`porting/nuttx/arch/arm/src/bk7258/` 保存 11 个学习注释文件；与
  NuttX 候选基线做去注释 token 对比，没有发现可执行代码变化。
- 应用层：本次 NSH 配置没有启用 `vision_badge`；ELF 中存在 `nsh_main`，不含
  `vision_badge_main`。

链接报告的静态 SRAM 占用为 5,252 B，ELF 入口为 `0x02010141`。这两个数值

bootloader，再通过 Beken packager 生成。离线检查确认：bootloader 位于
`0x0`，CPU0 应用从物理 Flash `0x11000` 开始，34/32 解码后的应用内容与
`nuttx.bin` 完全一致，镜像结尾为 `0x2db000`。

## 2026-08-28 实机烧录与启动证据

使用 BKFIL 2.1.11.15、CH340 的 COM12、115200 波特率，将最终镜像写入
`0x0-0x2db000`。工具日志依次报告：

```text
Gotten Bus
EraseFlash ->pass
WriteFlash ->pass
Boot_Reboot
Writing Flash OK
{All Finished Successfully}
```

复位后串口出现 `NuttShell (NSH)` 和 `nsh>`。已验证：

- `uname -a` 识别为 `arm bk7258-r1`；
- `free` 报告 336,760 B 用户堆，首次读取约使用 7.8 KiB；
- `/dev` 中存在 `console`、`ttyS0`、`null`、`zero`；
- `/proc` 已挂载，`ps` 显示 CPU0 idle 线程和 NSH 任务；
- UART0 可以接收命令并返回结果。

已发现但未混入本次修复的限制：`uptime` 不增长，`sleep 5` 不能返回。
当前 defconfig 没有启用架构定时器和 Armv8-M SysTick，下一提交将单独修复并
重新实机验证。`dmesg` 返回 `open failed: 2`，表示当前没有可供该命令读取的
系统日志设备或缓冲区，不影响 NSH 串口交互结论。

## 打包边界

当前镜像只组合 Beken normal bootloader 与 NuttX CPU0 分区，不包含 CPU1/CPU2
ARMINO 应用。分区参数参考当前 R1/AIDK 工程：bootloader 68 KiB，CPU0 物理
偏移 `0x11000`，分区 2856 KiB，并由 Beken packager 处理 34/32 线性 CRC。

本次实机结果说明 CPU0 镜像能够从 bootloader 启动并进入 NSH，CPU0/NSH 的
最小启动门禁已经通过。系统时钟、GPIO、外设总线、PSRAM、CPU1 和多媒体仍是
后续独立门禁，不能由本次结果外推为已经适配。
