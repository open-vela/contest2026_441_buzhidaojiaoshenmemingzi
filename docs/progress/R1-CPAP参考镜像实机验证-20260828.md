# R1 CP/AP 参考镜像实机验证

日期：2026-08-28。

## 验证对象

- 镜像：`bk7258-r1-openvela-all-app.bin`
- SHA256：`857410c4f491a37c53bebf63db134a4169e7fdc22d72599239c7aaf84a554bdf`
- 组合：物理 CPU0 运行 Armino CP，物理 CPU1 运行 OpenVela/NuttX AP；CPU2
  未进入当前 NuttX 调度。
- 用途：复核公开实现能否在本队 R1 上工作，不把参考应用算作本队最终成果。

CP 生成配置确认 `CONFIG_FREERTOS_V10=y`、`CONFIG_FREERTOS_SMP=n`、tick 为
1000 Hz。Armino 是 Beken SDK，CPU0 当前实际内核是 FreeRTOS v10。

## CP/AP 启动与控制台

CP 完成 EasyFlash、PSRAM、RF/Wi-Fi 初始化后启动 AP。AP 日志确认：

- Mailbox UART0 link ready；
- CPU1 boot-ready handshake 和 2 秒 heartbeat 建立；
- PSRAM、ramdisk、SD-NAND、按键、PWM、显示、Camera、Audio 和 JPEG 驱动完成
  bring-up；
- `ap_console open` 能从 CP 的 `$` 切换到 AP 的 `nsh>`，退出组合键能返回 CP；
- 桥接状态为 `ready=0x7 state=3 link=ready`，`drop/qfail/badenv` 均为 0。

AP 基础命令实测：

- `uname -a`：`NuttX 0.0.0 dd92bcf425-dirty ... arm bk7258-ap`；
- `uptime`、`free`、`ps`、`help`、`ls` 和 `/proc` 可用；
- `/proc/cpuinfo` 只有 `processor: 0`，这是物理 CPU1 在 NuttX 内部的逻辑
  CPU0，不能据此声明 CPU2 SMP；
- `/dev` 中存在 `fb0/fb1`、`video0/video1`、`audio/pcm0c`、`audio/pcm0p`、
  `mmcsd0/mmcsd0p0`、`pwm0` 和 `ttyMB0`。

## 显示实测

两块 GC9D01 均完成初始化，`/dev/fb0`、`/dev/fb1` 注册成功，日志分别记录多次
51200 字节 framebuffer 更新。实物复位时两块屏均出现启动画面；进入 idle 后只有
一块屏保持 `idle`，另一块为空。因此可以确认双屏硬件写入链已通，但最终双屏 UI
状态仍不一致，不能标记为完整显示功能通过。

## JPEG 与 Camera 实测

先用内存中的合成 YUV 验证软件编码器：

```text
jpeg_test enc -n 1
320x240 YU12, 115200 bytes -> 4267 bytes, 105 ms, valid JPEG
```

再执行真实 Camera 单帧：

```text
jpeg_test cam -d 0
sensor chip ID = 0x2145
640x480 30fps, VYUY, 614400 bytes
frame 0 -> 22051 bytes in 567 ms, valid JPEG
```

这次运行证明了 GC2145 的上电、Reset、MCLK、I2C、585 项初始化表、DVP pinmux、
YUV buffer、DMA/IRQ、PSRAM 帧缓冲、单帧采集和软件 JPEG 编码链。退出统计为
`frames=1 timeouts=0 rejected=0`，YUV ISR 记录 `frame=1 vsync=1 err=0`。

`valid JPEG` 当前只证明编码器检查到了正确 JPEG 结构；还没有把该帧导出到电脑
解码，也没有完成 100 帧循环和资源趋势检查，因此 P5 尚未全部关闭。

## 尚未完成

- 当前运行的是公开参考板级/驱动与测试应用，不是本队 `vision_badge` 的 Camera
  后端；
- Wi-Fi 只完成 CP 初始化，日志提示没有保存的 NAND 配网信息，未验证扫描、连接、
  DHCP、DNS 和 TLS；
- Audio 只有设备节点和 IPC 线程，未验证真实录音与播放；
- CPU2 没有进入 NuttX SMP；
- 一块屏进入 idle 后为空，需在本队 UI 接入时确定期望的双屏职责；
- 射频日志报告 polar table magic 为 `0xffffffff`，后续联网测试需观察校准和性能。
