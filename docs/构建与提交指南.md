## 3. 构建后检查

先找到当次 `out/bk7258/` 下的构建清单和 CP/AP 输出目录，再保存：

```bash
arm-none-eabi-gcc --version
grep -E 'CONFIG_(ARCH_CHIP_BK7258|BK7258_AP_CONTROL|BK7258_RPTUN|BK7258_AP_CORE|SMP|SMP_NCPUS|BK7258_WIFI_VNET)=' \
  <cp-or-ap-build>/.config
arm-none-eabi-readelf -h -l <cp.elf>
arm-none-eabi-readelf -h -l <ap.elf>
arm-none-eabi-size <cp.elf> <ap.elf>
sha256sum <cp.elf> <ap.elf> <cp.bin> <ap.bin> <final-image>
```

检查重点：

- CP `.config`：CPU0、AP control/supervisor、RPTUN、Wi-Fi VNET 和 NSH 为 `y`；
- AP `.config`：AP core、IPI、SMP、`SMP_NCPUS=2`、RPTUN 和所需外设为 `y`；
- CP/AP LOAD 段不越界，共享内存地址与两侧配置一致；
- 镜像只包含计划写入的区域，不用其他开发板的 RF/MAC/EasyFlash 数据。

## 4. 烧录与最小验收

用户使用 BKFIL 烧录经过哈希确认的终版镜像。烧录前关闭串口终端和其他占用
COM 口的软件。只有 BKFIL 输出 `Writing Flash OK` 才算写入成功。

启动后至少执行：

```text
uname -a
apctl status
sleep 3
apctl status
bkwifi status
```

通过条件：

- CPU0 进入 NSH；
- AP 为 READY，heartbeat 在两次查询间增长；
- RPTUN 为 CONNECTED；
- CPU2 为 SCHEDULER_ONLINE；
- AP SMP 为 PASSED；
- Wi-Fi 未连接时返回可解释状态，连接后能完成关联、DHCP、DNS；
- 双屏、Camera/Audio 等只在相应终版日志真实通过后标记完成。

每份日志头部记录 Git commit、镜像 SHA256、日期和测试命令，再放入
`evidence/final/`。
