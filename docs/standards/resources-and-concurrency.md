# 资源、并发与生命周期规范

## 内存与缓冲

- R01：每种缓冲明确分配域、对齐、容量、producer、consumer和释放函数；禁止跨系统堆、SDK私有池或DMA池释放。
- R02：启动前检查峰值预算，不只统计常驻内存；同时考虑JPEG、PCM、网络队列和线程栈。
- R03：DMA缓冲的物理可访问性、缓存属性与对齐由驱动接口约束；不因普通堆分配成功就假设可供DMA。
- R04：零拷贝接口说明借用期限；归还frame或audio buffer后不得继续读取其指针。
- R05：多消费者使用明确引用/复制或单一owner，禁止依靠“通常不会同时访问”。
- R06：错误路径释放已获得的资源；每种资源的有效标志随获得/释放更新，避免双重释放和泄漏。
- R07：敏感临时数据按生命周期清理；日志仅保留必要元数据，禁止自动落盘采集内容。

## 锁与执行上下文

- R08：共享对象明确锁或原子协议；volatile不提供互斥、内存顺序或跨核可见性保证。
- R09：维护锁顺序。不得在持有A时等待可能反向获取A的回调、worker或网络请求。
- R10：IRQ、spinlock区和实时音频回调中不得阻塞网络/文件、无限等待、线程join或动态大分配。
- R11：持锁只保护最小共享状态；慢操作移出锁后，用generation/状态复核防止提交到已变更会话。
- R12：在锁内形成对象快照，锁外使用时须保证对象生存期；释放锁不代表指针自动安全。
- R13：调用外部回调前查重入约定，避免持内部锁调用可能反向进入模块的函数。
- R14：原子变量明确内存序和发布对象；需要整体一致的多个字段不能只各自atomic后假定快照一致。
- R15：同步通知与条件更新遵循同一协议，防止先发生通知后进入等待导致丢唤醒。

## 队列与实时路径

- R16：队列容量、单帧上限、producer频率与consumer预算明确；满时按合同拒绝/丢弃/背压，不能无界增长。
- R17：实时采集路径只做有界搬运和必要元数据更新；识别、JSON、编码和网络交由明确消费者。
- R18：保留进度序号与连续性统计，区分短读、重复、丢帧、过期和主动停止。
- R19：每轮工作量有上限，防止持续短写或持续消息占用工作线程；不靠高优先级掩盖consumer不足。
- R20：取消与关闭能唤醒等待者；发送线程不得在永久阻塞状态等待已被清理的对象。

## 时间、退出与恢复

- R21：期限使用单调时钟；端到端传递绝对deadline，各阶段消耗剩余预算，不能重复发放完整超时。
- R22：音频采样序号、硬件计数和系统时间用途不同，转换须说明频率/回绕/单位。
- R23：stop顺序明确为停止新生产→取消待办→唤醒/排空→归还缓冲→关闭/销毁；按实际设备合同调整。
- R24：只在资源确实释放后允许新owner进入；取消标志本身不等于worker已经退出。
- R25：generation/请求ID跨重启和会话变化更新，拒绝旧ACK、旧frame或迟到的工具结果。
- R26：恢复有重试次数、间隔与总期限；重试前先回收旧资源，不在失败时叠加新线程或连接。
- R27：重连本地服务与重开云会话是不同操作，不能把前者顺带升级为隐式收费重试。
- R28：睡眠前确认媒体、RPC、存储事务的退出边界；屏幕熄灭不能替代实际睡眠或耗流测量。
- R29：信号处理只做允许的轻量操作，复杂清理由正常执行上下文完成。
- R30：资源统计用于判断泄漏、退出和恢复；统计归零与实际无持有对象分别核对。
