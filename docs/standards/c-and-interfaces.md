# C函数与接口规范

## 文件与可见性

- C01：源文件先给出许可和模块说明；按头文件、宏/类型、私有声明、私有数据、实现与公开接口组织。头文件使用包含保护。
- C02：新增C代码两空格缩进，不使用Tab；花括号单独成行，避免一行多个语句。相邻条件与复杂表达式按逻辑拆行。
- C03：包含直接使用的声明，不依赖偶然的传递包含。头文件只暴露调用者需要的接口，平台私有细节留在实现中。
- C04：私有函数/数据使用static；不为方便测试暴露无关全局变量，不在头文件定义可写全局对象。
- C05：函数和变量使用清晰的小写模块前缀，宏常量大写；名称说明动作或条件，长度/时间变量带单位，如bytes、frames、deadline_ms。
- C06：注释解释合同、原因和约束，避免复述代码；删除失效注释，不以注释掉的旧代码充当版本记录。

## 函数设计

- C07：每个函数负责一个清楚的操作或状态转换。一个函数同时编排网络、驱动和恢复时，按owner/阶段拆分，不按任意行数机械切割。
- C08：嵌套过深优先先处理无效输入、分离阶段或命名辅助函数；禁止以隐式跳转掩盖状态变化。
- C09：公共接口、驱动回调、跨线程和跨核入口必须说明参数方向、有效范围、返回值、执行上下文、是否阻塞、锁要求、所有权和错误后状态。
- C10：只读对象使用const。输出参数失败时是否有效必须明确；不能让调用者将未初始化的输出当成功数据。
- C11：同一模块动作接口与条件接口分开：动作按约定返回错误码，条件返回bool，字节数量接口返回实际处理数量；不得混用。
- C12：接口扩展优先新增明确字段/版本或专用函数；避免若干布尔开关组合成难以理解的多态行为。
- C13：禁止在看似查询的接口中顺便重启、关闭资源、修改配置或启动收费会话；副作用须明确可见。
- C14：重复stop/close和失败回收遵循幂等合同；start忙时返回可解释状态，不重复创建owner。

## 类型与输入边界

- C15：内存长度/容量使用size_t；协议字段使用固定宽度整数；计数、索引、状态和错误分开表达。
- C16：窄化转换前校验范围，有符号与无符号混算前明确非负边界；移位量必须小于类型位宽。
- C17：分配数组前检查乘法溢出，拼接长度前检查加法；检查len不超过capacity后再读写。
- C18：校验指针与长度的组合语义；允许空数据时明确NULL/0合同，禁止只检查指针后相信长度。
- C19：外来枚举、RPC长度、字符串终止、JSON类型和文件大小都在信任边界验证；内部assert不代替输入检查。
- C20：不直接把未对齐网络缓冲强转为结构体；处理字节序和字段序列化，防止padding或指针泄漏。
- C21：字符串复制保留终止空间并检查截断；二进制缓冲不得靠strlen确定长度。
- C22：宏不能重复求值有副作用的参数，不得隐藏return、锁或资源释放；可用函数表达时优先使用函数。

## 返回值与错误

- C23：NuttX内部接口按负errno约定；POSIX调用按-1/errno合同处理。跨层转换仅在边界完成并保留错误来源。
- C24：检查有意义的返回值。忽略错误必须说明为何不影响状态，不能把释放失败、短写或队满转换为成功。
- C25：read/write/send处理部分进度、EINTR、EAGAIN、0和对端关闭；重试不重复发送已成功前缀。
- C26：错误码保留用于定位，日志标出阶段；不得只打印error后丢掉原返回值。
- C27：按资源获得顺序反向回收，统一清理标签按实际资源命名；不跳过初始化进入释放路径。
- C28：assert表达程序内部不变量，不用于处理可预期的网络、资源不足或用户输入错误。
- C29：状态更新与资源提交一致；资源未取得前不能发布READY，失败时撤销已发布的临时状态。
- C30：超时、主动取消和完整成功分别表示，不能把有意停止的播放统计成完整播放通过。

## 接口合同最小内容

```text
Purpose       单一职责与允许的状态转换
Inputs        参数方向、单位、范围和有效期
Outputs       成功时数据、失败时有效性
Return        错误码/计数/条件的明确合同
Context       IRQ / callback / task，阻塞性和锁要求
Ownership     谁分配、何时交接、谁释放
Cancellation  deadline、取消唤醒、退出后状态
```
