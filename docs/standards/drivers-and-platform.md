# 驱动与平台适配规范

## 分层与配置

- D01：通用SoC寄存器/IRQ/DMA放芯片层，具体引脚/器件/电源时序放板层，产品交互放应用层。
- D02：应用优先使用标准子系统；无法直接映射的SDK能力封装在硬件边界，禁止散落到业务状态机。
- D03：新增驱动同时审查Kconfig、源文件选择、依赖、链接、板级注册和设备节点，不能只添加一个.c文件。
- D04：配置配对写明CPU角色、共享区与分区。使用生成.config验证最终选择，不只看defconfig。
- D05：新板先确认器件ID、引脚、电源、存储和总线；同一芯片不等于同一开发板。
- D06：寄存器/时钟/Flash布局常量注明依据或符号定义，禁止把另一板的校准/MAC/用户分区带入。
- D07：保留SDK和框架ABI边界；结构体大小、枚举值、调用约定发生跨库使用时用可检查合同保护。

## 注册与生命周期

- D08：区分芯片启动、系统调度就绪、deferred bring-up和产品启动；慢外设初始化不能阻塞基础跨核健康状态。
- D09：probe/initialize失败时撤销已注册节点和已分配资源，返回原始阶段错误。
- D10：首次open、重复open、最后close、shutdown、pause和stop的调用关系按固定upper-half源码核对。
- D11：不能因参考版回调同名就照搬阻塞清理；确认上层是否持锁、是否IRQ上下文。
- D12：设备状态区分未初始化、准备中、运行、停止、故障和恢复，禁止用单个ready掩盖多个不兼容状态。
- D13：硬件启动成功后再发布数据可用；启动失败不发送假frame/零填充音频代替实际采集。
- D14：close与重新open检查残留中断、DMA、队列、FD、任务和缓冲，不能只取消一个标志。

## DMA、媒体与中断

- D15：IRQ先确认并清除对应事件，保护最小状态后交给worker；不在ISR执行业务解析。
- D16：DMA传输前后按方向处理cache，明确descriptor与payload的可见性；内存屏障与cache操作不能互相替代。
- D17：驱动缓冲容量、有效长度和当前偏移分别维护，避免重复回放、越界与截断。
- D18：帧接口声明新鲜度、序号、尺寸和归还方式；旧预览frame不能冒充本次新观察。
- D19：Audio消费者准备、缓冲入队与硬件START顺序明确；启动提示不能在实际保留声音前宣称就绪。
- D20：采音/播放/相机并发需检查中断、总线、DMA、堆域与调度预算；软件状态机存在不代表硬件并发已验证。
- D21：显示初始化、渲染提交与实际像素可见分别验证；在产品文档中按显示的真实用途说明。

## 多核与电源

- D22：区分物理CPU、逻辑CPU和操作系统实例；共享内存/向量/栈/链接地址两侧一致。
- D23：RPTUN通知、pending、generation和endpoint关闭有明确顺序，防止旧代消息提交到新对象。
- D24：heartbeat区分启动阶段、在线与健康；不以一条READY日志代表持续存活。
- D25：IPC payload校验版本、长度、命令、权限和序号；跨核结构不得传递只在另一地址域有效的指针。
- D26：电源prepare与真正睡眠分开；先排空媒体、同步存储并取得必要屏障，再执行底层切换。
- D27：唤醒后先恢复必要PM/时钟/计时条件，再判断按键门限或启动外设；不依赖休眠前的过期时刻。
- D28：保留手动恢复与回退路径；不在调试失败时整片擦除来回避分区或ABI问题。

## 适配验证

- D29：按启动→多核/跨核→设备注册→实际I/O→重开/取消的依赖关系验证，不跳过最低层故障。
- D30：使用真实被修改实现覆盖关键失败路径；只mock硬件边界，不能将关键guard/owner全替换成成功。
- D31：已有框架、SDK或公开BSP基础与本项目差分分别标明，内容相同不声称新增实现。
- D32：静态接口审查、构建、模拟和板端行为各留证据，不用代码行数推导驱动完成度。
