# MVP 验收标准

## 平台前置门槛

BK7258 R1 的平台能力按下表验收；编号不是严格串行顺序。应用主机开发可并行，
单项实机功能只要求通过其依赖能力；例如离线相机不依赖 P4 网络，第一阶段
控制台闭环不要求先完成第二阶段的双麦录放音：

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P0 | 硬件/版本冻结 | R1 修订、器件型号、原理图依据和全部 commit 可追溯 |
| P1 | 构建与镜像 | clean build 可重复；分区、CRC、镜像哈希和恢复流程明确 |
| P2 | CPU0/NSH | 冷启动 10 次均进入交互 NSH，UART RX/TX、SysTick、heap 正常 |
| P3 | PSRAM/GPIO | PSRAM 边界与压力测试通过；按键/振动至少一个 GPIO 闭环 |
| P4 | Wi-Fi/TLS | `wlan0` 获取地址；DNS、HTTPS、断网恢复通过 |
| P5 | Camera | `/dev/video0` 连续取单帧 100 次，图片可解码且无持续泄漏 |
| P6 | Audio/反馈 | 60 秒 PCM 无溢出；至少一种非视觉反馈稳定 |

公开 PR 作者的测试只能作为参考，必须在本队收到的 R1 上重新留证。

## 第一阶段：最小视觉闭环

| 编号 | 验收项 | 通过标准 | 证据 |
| --- | --- | --- | --- |
| M1 | openvela 启动 | 连续冷启动 10 次均进入 NSH，无崩溃/重启 | 串口日志、固件版本 |
| M2 | Wi-Fi 与 HTTPS | `wlan0` 获取地址；连续 20 次测试请求成功率 ≥ 95% | `ifconfig`、请求统计、错误码 |
| M3 | V4L2 单帧 | `/dev/video0` 连续取帧 100 次，无泄漏，成功率 ≥ 99% | 帧尺寸、耗时、堆快照 |
| M4 | JPEG 数据 | 每张图片具备有效 JPEG 标记，可在主机解码；尺寸不超过配置上限 | 样本、哈希、大小统计 |
| M5 | MiMo 视觉请求 | 上传图片并得到可解析的有界结构化结果；超时/错误可恢复 | 脱敏请求日志、JSON、错误场景 |
| M6 | 用户反馈 | 至少一种反馈方式把有效结果或错误状态明确告知用户 | 视频/串口日志、测试记录 |

M1～M6 全部通过才称为“最小视觉闭环完成”。任何单项未留证据时状态保持“待验证”。

## 通用失败场景

- 摄像头节点不存在、取帧超时、JPEG 过大；
- Wi-Fi 未连接、DNS 失败、TLS 失败、HTTP 非 2xx、云端超时；
- JSON 截断或字段缺失；
- 内存申请失败、连续运行后碎片上升；
- 音频设备不存在或振动模块未连接。

所有失败必须：不崩溃、不泄露凭据、返回可定位错误、提供至少一种状态反馈。
