的版本。当前最有价值的是同一作者提交到 openvela 的两份配套 PR：

两份公共 PR 至今仍未合并，因此上游官方基线里仍没有可直接视为“已正式支持”的
BK7258 完整端口；但多个参赛队伍已经在各自专属仓中公开了不同成熟度的实现和实板
记录。队伍仓可用于缩短探索时间，仍不能等同于官方 BSP。一般 BK7258 FreeRTOS、
门铃或 WebRTC 项目只能作为外设行为参考，不能当作 openvela BSP。

## 对公开 PR 的成熟度判断

### 1. 能作为 P0 起点的部分

- CPU0 镜像入口、Flash XIP 与 SRAM 链接布局；
- bootloader 跳转后的 MSPLIM、FPU、看门狗处理；
- UART0 时钟/复用、禁止 soft-reset、RX FIFO 阈值；
- SYS 中断聚合器与 NVIC 的双层开关；
- SysTick、堆、NSH、线性 CRC 镜像打包；
- PSRAM 探测/加入堆、GC9D01 和双麦调试方法。

### 2. 不能直接沿用的部分

- R1 的 GPIO、LCD 选通、DVP、麦克风、振动和电源脚位；
- 公开 PR 中未获上游 review 的寄存器常量和私有实现；
- 依赖作者本机 ARMINO 路径/产物的打包流程；
- 把 ARMINO HAL 函数直接粘贴进 NuttX 的做法；
- 尚未证明的 480 MHz 运行频率、内存带宽或多核分工假设。

### 3. 收板后的第一项判定

用板卡丝印、SoC marking、USB-UART 芯片、Flash/PSRAM ID、屏幕和摄像头型号，
逐项对比公开 `bk7258-devkit`。只有原理图网络名和实测 ID 对得上，才允许把
PR #2 当作 R1 板级基线；否则建立独立的 `bk7258-r1` BSP，避免污染 DevKit。

## 声网示例能帮助什么

声网公开示例不是 openvela 移植，但它与发放套件最接近，优先用于：

- 对照 CPU0/CPU1/CPU2 的固件分区和启动顺序；
- 确认 DVP Camera 输出格式、分辨率、MJPEG/H.264 数据流；
- 确认双麦采集、AEC/NS、扬声器回放参数；
- 对照 Wi-Fi/蓝牙配网流程、按键、振动、NFC、显示和省电状态机；
- 在 openvela 驱动失败时，用原厂固件做 A/B 硬件排除。

不得混用出厂固件、配网工具、Demo App 和不同版本的开源代码。任何云端
App ID、Token 或服务地址只在运行环境注入。

## 版本与许可证策略

1. 在 `docs/progress` 记录采用的 PR commit、ARMINO tag、工具链和 R1 修订号；
2. 上游 PR 未合并前，不把其源码复制进队伍仓；需要实验时在独立工作区 fetch；
3. 真正需要修改 `nuttx` 或 `vendor_beken` 时，从对应仓 fork、分支提交并向
   `dev-ai-contest-2026` 发 PR；
4. 移植实现优先依据公开文档重新编写，引用代码必须保留原许可证与来源；
5. PR 更新或 force-push 后重新做差异审查，不能只信旧 commit 的结论。
