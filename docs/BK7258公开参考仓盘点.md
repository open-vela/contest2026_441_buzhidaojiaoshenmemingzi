# BK7258 公开参考仓盘点

更新日期：2026-08-27。

这份清单用于后续 BK7258 R1 移植时快速定位可借鉴的现成实现。它不是“完成度排行榜”，也不把其他队伍的自述直接当作本项目证据。任何代码进入本项目之前，仍需经过来源、许可证、目标板差异、构建和实机五项复核。

## 检索范围与结论

本次通过 GitHub API 枚举 `open-vela` 组织下 464 个公开的 `contest2026_*` 仓库，递归扫描每个默认分支的文件树，并用 `BK7258`、`CONFIG_ARCH_CHIP_BK7258`、`BK7258_AIDK`、`bk7258_start.c`、`CONFIG_BK7258` 五组代码关键词交叉复核。

经过代码、构建记录和实机证据过滤，最终只保留 4 个可用于本项目的参考仓库：264、135、098、272。清单不收录仅有目录、占位实现、来源边界不清或声明明显超过证据的仓库，避免后续误用。

这个数字只覆盖 `open-vela` 组织中公开、已推送到默认分支且能被 API 读取的内容，不覆盖队员个人 fork 的未合并分支、尚未推送的本地代码和私有仓库。

## 后续实施时的参考顺序

### 第一阶段：保持当前最小 NSH 目标

1. 继续固定当前 PR #332/#2 基线，先让本项目的 `bk7258-r1/nsh` 产物可重复构建。
2. 用 098 对照同类 R1 的 UART、PSRAM、屏幕、Camera 电源和引脚事实。
3. 用 272 的启动契约和故障记录方式补强冷启动、交互 NSH、异常寄存器和镜像哈希证据。
4. 不在此阶段引入 Wi-Fi、应用 UI 或完整 CP/AP 改造，避免一次同时改变启动链和系统拓扑。

### 第二阶段：决定最终 CPU 拓扑

拿到板后先验证 CPU0-only NSH。基础证据稳定后，再比较：

- 保持 CPU0-only：实现简单，适合最早 NSH，但原厂无线/媒体能力复用困难；
- CPU0 保留 Armino CP，CPU1/CPU2 运行 OpenVela AP：更接近 264/135 的完整产品路线，能复用无线控制器、打包和多核通信，但复杂度更高。

这个选择必须由本项目实测和最终功能依赖决定，不能因为其他队伍采用某种方案就直接跟随。

## 复用红线

1. public 只代表“可读”，不代表“可任意复制”。所列队伍仓根目录均未发现统一的 LICENSE 文件；只能逐文件检查 SPDX、来源和上游许可证。
2. 优先依据 R1 原理图、Beken 官方 SDK/文档和 Apache-2.0 源码重新实现；复制允许复用的文件时保留 SPDX、版权和来源。
3. 不复制其他队伍的产品创意、应用业务逻辑、README 宣传和 AI 日志；只借鉴已理解的通用硬件适配方法。
4. 每次采用外部实现都记录：来源 URL、固定 commit、原文件、采用范围、本地改动、许可证、构建结果和实机结果。
5. 构建成功不等于 R1 硬件通过；其他板通过也不等于 R1 通过；文档中的日志摘录也不等于本项目自己的证据。

## 刷新方法

比赛临近截止，仓库每天都可能更新。开始任何新阶段前至少重新检查：

```sh
git ls-remote <仓库 URL> refs/heads/dev-ai-contest-2026
```

若 HEAD 变化，先阅读新提交和差异，再决定是否更新参考提交。不要在未审查的情况下自动同步或覆盖本项目代码。
