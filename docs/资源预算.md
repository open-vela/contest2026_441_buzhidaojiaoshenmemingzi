# BK7258 R1 资源预算

本文只给出可计算的数据量和应用保护上限。芯片内存、R1 的 Flash/PSRAM 容量、
CPU 实际频率及可用分区必须以原理图、器件 ID、链接 map 和真机日志为准。
公开 PR 报告的 16 MB PSRAM 和 336 KiB CPU0 SRAM 只能作为待复核参考。

## 可直接计算的数据量

| 数据 | 计算 | 大小 |
| --- | --- | --- |
| QVGA RGB565 | 320 × 240 × 2 | 153,600 B（150 KiB） |
| VGA RGB565 | 640 × 480 × 2 | 614,400 B（600 KiB） |
| 双屏 RGB565（160 × 160 × 2） | 160 × 160 × 2 × 2 | 102,400 B（100 KiB） |
| 1 秒单声道 PCM | 16,000 × 16 bit | 32,000 B（31.25 KiB） |
| 1 秒双声道 PCM | 16,000 × 16 bit × 2 | 64,000 B（62.5 KiB） |

VGA 原始帧不能放入公开 PR 所述的 336 KiB CPU0 SRAM，Camera 帧应优先放
PSRAM，并用分片/双缓冲控制 DMA 和网络发送。

## 初始应用上限

| 缓冲 | 初始上限 | 说明 |
| --- | ---: | --- |
| JPEG | 256 KiB | Kconfig 可调；P5 以真实图片分布校准 |
| 结构化结果/JSON | 32 KiB | 超限拒绝，不无界扩容 |
| 网络发送 | 16 KiB 级 | 以 TLS/netdev 实测调整 |
| 主命令栈 | 8 KiB | 按栈高水位校准 |
| PCM 环形缓冲 | 32～64 KiB 起步 | 分片处理，不保留完整长录音 |
| TLS 工作内存 | 待测 | 取决于证书链、算法和库配置 |

## 内存策略

2026-08-26 静态复核：当前 `vision_badge_run()` 同时 `malloc` 256 KiB 图像
和 32 KiB 结果缓冲，共 288 KiB，占候选 336 KiB SRAM 的约 85.7%。仅剩
48 KiB 供静态段、内核、堆管理和任务栈等使用，尚未计入网络/TLS。候选
板级代码没有为本应用提供已经验证的 PSRAM 分配路径，所以这两个上限不是
当前 SRAM-only 配置的可用性承诺。分配失败已有释放并报错路径，但是否能够
成功分配仍须结合链接 map、NSH 空闲堆和最大连续块实测。P2 可先运行
`status` / `selftest`，它们不分配这两个大缓冲；进入 P5 前必须重算内存布局。

1. P2 记录 NSH 空闲堆、最大连续块、任务栈和链接 map；
2. P3 验证 PSRAM 边界、对齐、cache 和 DMA 可达性；
3. P5 记录 Camera 打开、取帧、JPEG 和重复 open/close 的每个峰值；
4. P4/P7 记录 DNS、TLS 握手、上传、接收和 JSON 解析峰值；
5. 图像、上传和结果缓冲错峰复用，避免多份 VGA 副本；
6. 100 轮后比较最大连续块，判断碎片是否持续恶化。
