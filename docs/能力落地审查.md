# 图形、AI、多媒体能力落地审查

审查日期：2026-08-26

判定口径：必须存在本项目实现，并有目标硬件上的可复现运行证据。规划、接口、设备探测、上游样例或 mock 不等于落地。

| 能力 | 当前结论 | 依据 | 达标缺口 |
| --- | --- | --- | --- |
| 图形 | 未落地 | BK7258 R1 配置和应用中没有团队实现的 LCD/LVGL 显示闭环 | 显示驱动、应用画面和 R1 实机证据 |
| AI | 未落地 | 视觉服务调用链已搭建，但推理后端仍返回 ENOSYS | 真实图片输入、模型/服务结果、时延及失败证据 |
| 多媒体 | 未落地 | 相机和音频仅有探测/接口骨架，采集或录放后端仍返回 ENOSYS | 真实 V4L2/DVP 或 PCM 数据、格式/数量及资源证据 |

因此，当前项目尚未落地图形、AI、多媒体三项能力中的任意一项。它处于可审查的基础框架阶段，不能在申报材料中写成“能力已完成”。

本轮已经通过[两套 ARM 固件构建与应用符号核对](progress/构建验证-20260826.md)，但仍未在 R1 执行；上述能力结论不因“编译成功”而改变。MiMo 作为开发助手的评审调用，也不等于设备应用已经具备 AI 功能。

## 最短落地路径

优先落地多媒体中的相机能力：通过 openvela/NuttX Camera/V4L2 路径获取真实 JPEG，连续采集至少 100 帧，记录尺寸、格式、主机解码结果、错误计数和内存变化；哈希用于关联样本，不能替代有效图片验证。随后把同一真实图片交给视觉服务，完成 AI 闭环。图形显示可在硬件资料和驱动基线明确后追加。

## 复查

运行：

```sh
python .agents/skills/bk7258-openvela-porting/scripts/audit_project.py . --json
python -B .agents/skills/bk7258-openvela-porting/scripts/test_audit_project.py
```

脚本只用于发现代码信号和 ENOSYS 待审查项，未解析编译条件；缺失或无法读取关键文件时退出 2。最终结论必须结合构建、烧录和 R1 实机原始日志。

100 帧是本项目自定验收目标，不是大赛统一强制指标。相机离线采集可独立于 Wi-Fi 推进；联网 AI 闭环再依赖网络阶段。
