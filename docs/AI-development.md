# 规则约束下的AI开发

维护者负责场景、需求、规则与Review，AI在约束下完成接口核对、实现及针对性自检。交付依靠实际代码、配置和验证结果，而不是将对话本身当作正确性证明。

```text
需求与规则 → 接口/资源合同 → AI实现 → 自检及证据
                                   ↓
                  维护者Review → 修改 / 接受 → 交付
```

规则分为C接口、资源/并发、驱动平台、服务端工具和验证Review五部分，入口为CONTRIBUTING。平台Skill把板型输入、分层定位、接口审查和交付检查整理为可重复流程；使用者提供自己的板型、配置与版本，不照抄R1引脚或机器路径。

开发案例应以具体问题、代码差分、失败与验证说明。自动检查、功能反馈和人工代码Review分别记录，不以任何一种替代另外两种。
