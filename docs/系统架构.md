# 系统架构

## 分层

```text
vision_badge 应用
├── workflow
├── camera_service
├── vision_service ───────────── MiMo Vision
├── audio_service
└── feedback_service
        │ 标准 openvela / NuttX 接口
        ▼
V4L2 / Audio / Netdev / GPIO / LCD
        │ BK7258 chip + R1 board 层
        ▼
DVP Camera · 双麦/AEC · Wi-Fi · PSRAM · Speaker · 振动 · 双屏
```

应用层只依赖标准设备接口和负 errno，不直接包含 ARMINO 头文件。Beken 厂商库
如必须使用，应封装在 `vendor_beken` 内，并明确线程、内存、许可证和多核边界。

## 核心数据链

```text
按键/语音触发
      │
      ▼
Camera Service ── V4L2 /dev/video0 ── 单帧 JPEG（PSRAM）
      │
      ▼
Vision Service ── wlan0 + HTTPS ── MiMo Vision
      │                                │
      └──── 有界结构化结果 ◀───────────┘
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
         控制台       Speaker/TTS    GPIO/PWM 振动
```

## 平台启动链

```text
BootROM → Beken bootloader → CPU0 NuttX __start
                         → 向量/FPU/MSPLIM/时钟
                         → UART0 + IRQ + SysTick + heap
                         → board bring-up / PSRAM
                         → NSH / vision_badge
```

公开 bring-up 选择 CPU0 是为了直接拥有 UART0。最终是否保留厂商 CPU1/CPU2
固件及其 Wi-Fi/A/V 任务，要以 R1 SDK 的启动契约为准；任何跨核服务都要记录
mailbox/RPC、共享内存 ownership 和 cache 一致性。

## 模块责任

| 模块 | 输入 | 输出 | 当前状态 |
| --- | --- | --- | --- |
| `workflow` | 用户问题、图像/结果缓冲 | 阶段和错误码 | 骨架完成 |
| `camera_service` | V4L2 路径、缓冲 | 单帧 JPEG | 节点探测完成；BK7258 驱动待 P5 |
| `vision_service` | JPEG、问题 | 有界文本/方向 | 接口完成；Wi-Fi/TLS/MiMo 待 P4/M5 |
| `audio_service` | PCM 缓冲 | 录音长度 | 节点探测完成；BK7258 音频待 P6 |
| `feedback_service` | 结构化结果 | 控制台/音频/振动 | 控制台基线完成，其余待 P6 |

当前未实现后端统一返回 `-ENOSYS`，避免调用方把占位实现当成功。

## 运行约束

- 每次只处理一个请求和一张图，不并发上传多帧；
- Camera、TLS、JSON 与 Audio 大缓冲错峰，真实峰值以真机测量为准；
- DMA 缓冲明确 cache clean/invalidate 和所有权切换；
- 请求/响应设置尺寸、连接和读取超时；
- API Key、Wi-Fi 密码、校准数据和私钥不进入仓库或 AI 日志；
- 云端不可用时返回明确错误并给出本地反馈，不生成伪答案。
