# BK7258 R1 系统架构

本文是项目唯一的系统总图。它描述终版目标、已经得到的证据，以及源码到开发板
运行的真实关系。历史上的 CPU0 Armino + AP OpenVela 路线只保留为外设对照，
不再作为终版架构。

## 1. 三颗物理 CPU 与两个 NuttX 实例

```text
                 BK7258
┌──────────────────────────────────────────────────────────────┐
│ 物理 CPU0：CP NuttX/OpenVela                                 │
│  复位向量 → __start → nx_start → NSH                         │
│  AP 控制/监督、RPTUN 主端、UART0、Wi-Fi VNET 诊断             │
│                         │ Mailbox + 共享 SRAM                 │
│                         ▼                                    │
│ AP NuttX/OpenVela（一个 SMP 操作系统实例）                    │
│  ├─ 物理 CPU1 = AP 逻辑 CPU0：启动、bring-up、主要驱动       │
│  └─ 物理 CPU2 = AP 逻辑 CPU1：由 up_cpu_start 拉起并参与调度  │
└──────────────────────────────────────────────────────────────┘
```

“AP 双核”不是两套 AP 系统。CPU1、CPU2 共享同一个 AP NuttX 调度器和地址空间。
CPU0 则运行另一套 CP NuttX，通过 Mailbox、共享内存和 RPTUN/RPMsg 与 AP 通信。

## 2. 从源码到运行的总链路

```text
chips/bk7258 + boards/bk7258 + nuttx + app/bsp_diag
                         │
                         ▼
boards/bk7258/aidk_ai_toy/openvela.conf
        ├─ team441_cp/defconfig
        ├─ team441_ap/defconfig
        └─ bk7258_ab_fixed_block_full_release.csv
                         │
                         ▼
tools/bk7258/bk7258.py build
        ├─ CP：C → .o → archive → ELF/map → raw bin
        └─ AP：C → .o → archive → ELF/map → raw bin
                         │
                         ▼
地址/拓扑检查 → 32+2 CRC 编码 → Flash 分区镜像 → 构建清单/SHA256
                         │
                         ▼
用户使用 BKFIL 写入明确分区，保留 RF/MAC/EasyFlash/用户数据
                         │
                         ▼
BootROM/bootloader → CPU0 → AP CPU1 → AP CPU2 → RPTUN → bring-up
```

只有生成的 `.config` 中目标配置确实为 `y`，才说明 Kconfig 最终选择生效；仅在
defconfig 中写一行不算完成。终版构建必须保存 `.config`、ELF、map、bin、构建
清单和 SHA256。

## 3. 启动顺序与关键文件

| 阶段 | 关键文件 | 关键函数或结果 |
| --- | --- | --- |
| CPU0 复位 | `chips/bk7258/cp/bk7258_vectors.c` | `bk7258_reset_entry()` |
| CPU0 C 入口 | `chips/bk7258/cp/bk7258_start.c` | `__start()` 设置 VTOR/FPU、data/bss、时钟、UART 后进入 `nx_start()` |
| IRQ/节拍/堆 | `chips/bk7258/common/` | `up_irqinitialize()`、`up_timer_initialize()`、`up_allocate_heap()` |
| CPU0 board 入口 | `boards/bk7258/common/src/` | `board_late_initialize()`、`board_app_initialize()`、`bk7258_bringup()` |
| CPU0 拉起 AP | `chips/bk7258/cp/bk7258_ap_control.c` | 设置 AP 向量并等待 READY |
| AP 复位 | `chips/bk7258/ap/bk7258_ap_vectors.c` | CPU1 成为 AP 逻辑 CPU0 |
| AP C 入口 | `chips/bk7258/ap/bk7258_ap_start.c` | AP `__start()` → `nx_start()` |
| CPU2 SMP | `chips/bk7258/ap/bk7258_ap_smp.c` | `up_cpu_start()`，CPU2 scheduler online |
| AP 生命周期 | `chips/bk7258/ap/bk7258_ap_lifecycle.c` | 发布 READY 和 heartbeat |
| 跨核通信 | `chips/bk7258/common/bk7258_rptun*.c` | RPTUN CONNECTED、RPMsg endpoint |
| R1 外设 | `boards/bk7258/aidk_ai_toy/src/` | deferred bring-up 后逐项注册设备 |

SysTick 是调度、`sleep`、超时和跨核等待的时间基础。出现“NSH 能输入但 sleep
不返回”时，第一检查点是 SysTick/IRQ，而不是直接怀疑应用。

## 4. 内存与跨核边界

| 区域 | 地址/大小 | 所有者 |
| --- | --- | --- |
| AP spinlock | `0x28000000..0x2800ffff` | AP SMP |
| CP RAM | `0x28010000` 起，`0x40000` | CPU0 NuttX |
| AP RAM | `0x28050000` 起，RPTUN 配置下 `0x47000` | AP NuttX |
| RPTUN shared | `0x28097000` 起，`0x8000` | CP/AP 共享 |
| telemetry/shared page | `0x2809f000` 起，`0x1000` | 生命周期与心跳 |
| vendor PM / SWAP | `0x2809f700` / `0x2809f800` | 原厂保留 ABI |

这些地址由 `chips/bk7258/include/bk7258_amp.h`、CP/AP 链接脚本和分区生成规则
共同约束。修改其中一处而不更新其他位置，可能出现“能链接、启动后互相覆盖”。

## 5. RPTUN、状态与诊断

```text
CPU0 prepare resource table
  → AP TABLE_READY
  → CP/AP CONNECTING
  → 当前 generation 的 vring/endpoint 建立
  → CONNECTED
```

`apctl status` 用于区分：

- AP `FAILED`：AP 本身没有完成启动或被监督判定失败；
- RPTUN `CONNECTING`：AP 可能已运行，但跨核通信尚未建成；
- CPU2 未 `SCHEDULER_ONLINE`：AP 主核已运行，第二调度 CPU 未上线；
- heartbeat 不增长：AP 失活或跨核状态没有继续更新。

`bkwifi` 通过 CPU0 侧诊断入口调用 AP 所有的 Wi-Fi VNET 服务。`-107` 等后续
网络错误不能脱离 AP/RPTUN 状态解释；先找第一处失败。

## 6. R1 board bring-up

R1 引脚、电源和器件绑定属于 board 层；GPIO 寄存器、IRQ、DMA、UART/QSPI
控制器属于 BK7258 chip 层。同一 BK7258 的不同 board 可以共用 chip 层，但按键、
屏幕、电源脚不能写死在通用 SoC 代码中。

AP READY 之后再执行慢速外设的 deferred bring-up，避免 LCD、Camera 或存储故障
阻塞 AP 心跳和 RPTUN 基础链路。当前主要数据链为：

```text
双屏：framebuffer → GC9D01 → QSPI0/QSPI1 → LCD
相机：GC2145/I2C → DVP → YUV/DMA → PSRAM → JPEG → /dev/video0
网络：RF/PHY → AP Wi-Fi 服务 → VNET/RPTUN → CPU0 网络诊断
存储：SDIO → MMCSD → /dev/mmcsd0(p0) → VFAT
```
